# Stage: Eliminated Approaches (Do Not Retry)
- [ELIMINATED - C-72 / CDPR-82] Pure-Python `while x < 128:` byte-diff loop in `_flush_precompiled_pages`: takes ~2.5ms on cache-miss frames; replaced by C-int XOR + compiled regex (`~0.025ms`).
- [ELIMINATED - C-78] Writing `0x28` (400kHz) to `TWI0_CCR` in `finally:` on every sub-frame exit: causes 310 register transitions/sec on `0x05002014` and `[Errno 110]` bus timeouts.
- [ELIMINATED - CDPR-191] Sub-frame 240B payload budget with rotating page cursor (`_mv_p_cursor`) skipping pages across sub-frames: skipping a page on any sub-frame alters its 1/3 or 2/3 PWM duty cycle and causes severe flicker.
- [ELIMINATED - CDPR-194] Injecting `0xA8, 0x0F` (16MUX scan parking) into multi-page chunked flushes: causes row 0..15 multiplex wrap-around ("violent flicker along with ghost image aside").
- [ELIMINATED - CDPR-214] Overwriting `oled_pwm_dt` in `vipxpert_os.db` (`0.006451948 -> 0.006443948`): only affects the slow white scan bar, not fast gray flicker, and clobbers user PWM Sync Cal setting.
- [ELIMINATED - CDPR-166 / CDPR-214 / CDPR-224] Setting `target_ccr = 0x88` (1.2MHz) or removing `8-msg` (`range(0, len(tx_msgs), 8)`) chunking / `TWI0_SRST` (`0x1C=0x01`) recovery in `Display._flush_precompiled_pages`: wedges `mv64xxx_i2c` (`[Errno 110] Connection timed out`, `6202ms` freeze), forces I2C0 pin reset, and causes PCM5122 / Bluetooth audio loss and pauses. `0x90` + `8-msg` chunking + `0x1C=0x01` recovery is a hard hardware invariant.

# Stage: Isolation & Telemetry Plan
1. **Bug C Root Cause Found (`[P-230]`):**
   - In `BluetoothDaemon._parse_media_properties()` (`L183-211`), when a new track starts (`new_title != old_title`) and BlueZ's `Track` payload omits `Duration` (or sends `0`), `self.media_state['duration']` is NOT reset and retains the previous shorter song's duration (typically 120s..190s, >50% of Bad Apple's 219s).
   - In `LockScreenApp._extract_media_info()` (`L1492`), `pos = max(0.0, min(pos, dur) if dur > 0.0 else pos)` clamps `pos` at that stale `dur` forever once playback reaches `dur` (while seeking backward plays normally until `pos` hits `dur` again).
   - Also in `BluetoothDaemon._dbus_signal_handler()` (`L293`), when `State == 'active'` arrives without a `Position` update, `self.media_state['updated_at'] = now_t` is overwritten without accumulating elapsed time into `self.media_state['position']`, snapping `pos` backward to the last AVRCP `Position` checkpoint.
2. **Bug B Root Cause Found (`[P-223]` / `[P-230]`):**
   - `MusicVideoScene._ensure_mmap()` calls `_find_matching_video()` (running `os.walk()` across 5 directories + `os.stat(rules_json)`) on every 30 FPS UI frame before checking the open mmap fast-return.
   - `Display._flush_precompiled_pages()` (`L325-332`) runs a dead `viz_bytes` Python generator scan on `cur_ph == 2` even during `is_fs_pwm`.
3. **Bug A Root Cause Found (`[DPR-221]` / `[P-229]`):**
   - With `max_msgs <= 36` and `split_gap = 10`, speckled frames produce `avgM = 31.5..35.5` (`16..18 spans` = `5` separate `8-msg` `ioctl` chunks), spending `~3.2ms` in kernel `ioctl` STOP/START overhead alone (`io = 5.10ms, max = 6.82ms`, `slips = 153/292`). Coalescing small gaps `<= 22B` while refusing to merge gaps `> 28B` cuts `avgM` from `~33` (`5 chunks`) to `~16` (`2 chunks`) without bloating `avgB`.
